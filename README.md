Production-style React/Vite frontend for the existing CloudMGWR AWS backend.

## Features

- Email/password Cognito sign-in
- Self-service sign-up + email confirmation
- Forgot/reset password
- Dashboard with quota/VIP/account status and job history
- CSV header discovery in-browser
- Four-step MGWR configuration workflow
- Direct S3 presigned CSV upload
- Submit to the existing trusted `/jobs` backend route
- QUEUED/RUNNING polling every 5 seconds
- COMPLETED/FAILED/TIMEOUT/CANCELLED status display
- My Jobs list and job details
- Presigned artifact downloads
- Responsive, modern scientific UI

## Local development

```bash
npm install
npm run dev
```

Open the URL printed by Vite (usually `http://localhost:5173`).

The existing development CORS configuration currently allows this origin because it is using `*`.

## Environment variables

Copy `.env.example` to `.env.local` if you want to override the built-in defaults:

```bash
cp .env.example .env.local
```

Available variables:

```text
VITE_AWS_REGION
VITE_COGNITO_USER_POOL_ID
VITE_COGNITO_CLIENT_ID
VITE_API_BASE_URL
```

Do not put AWS access keys, AWS secret keys, Cognito client secrets, or other private credentials in this repository.

## Build

```bash
npm run build
```

Vite produces the deployable static site in `dist/`.

## Amplify Hosting

An `amplify.yml` file is included. Amplify should run:

```text
npm ci
npm run build
```

and publish `dist/`.

Because this app uses React Router with clean paths such as `/jobs/<job-id>`, configure an Amplify SPA rewrite from non-file routes to `/index.html` with HTTP 200. See `DEPLOYMENT_GUIDE.md`.


## v1.2 output contract

CloudMGWR v1.2 presents exactly two downloadable result files for completed jobs:

- `Local_results.csv`
- `Summary.txt`

The statistical contents are generated by `worker.py`. The frontend deliberately treats
both files as opaque downloads, so future statistical-output changes can be made in the
compute worker without redesigning the website, as long as these two filenames remain
stable.

The default parallel-worker setting is 185 and the current UI maximum is 192.
